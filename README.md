## 2. 页面结构（当前版本）

| 区域                                          | 内容                                                                                                                                                                                                                                                                                                            | 交互                                                                                      |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 标题栏                                        | 只有标题**WaraSplat**（写在 `data.js` 的 `meta.title`），页脚已去掉                                                                                                                                                                                                                                   | —                                                                                        |
| **Part 0 · Adverse Weather 3D Scenes** | 四类天气场景各一段视频，**宽屏一行 4 个**                                                                                                                                                                                                                                                                 | 静音自动循环播放，无任何控件                                                              |
| **Part 1 · Our Method**                | 12 个案例，**四排、每排三个**（一排一类天气）：**从左到右固定为 heavy → medium → light**；卡片标题只到强度（如 `Snow · GrassFlower · heavy`，不显示 high / low / middle）；每个案例 = 一个 **VolSplat ⟷ Ours** 视频滑杆                                                                | 每张卡片 1 根滑杆，拖它对比 VolSplat 与 Ours；进入视口自动播放                            |
| **Part 2 · Comparison**                | 四类天气 Tab（每类 3 个场景，卡片同样按 heavy → medium → light 从左到右）；**每个场景 = 三排**（6 种对比方法按 2 : 2 : 2 分组），**每排 = 2 种方法 + Ours + GT**（4 个画面叠在同一个 256×256 舞台里，**3 根细线滑杆**区分，**GT 在最右**），方法名**横向标在每块画面内**的顶部 | 每排 3 根滑杆都能拖；拖任意一根调整左右两块画面的宽度；双击滑杆恢复等宽；点击画面放大查看 |

### 页面上的"少即是多"

- **没有任何播放控件**：没有 ▶ 播放 / ⟲ 重播 / 进度条 / 时间 / 循环 / 1x / 静音，也没有工具栏和说明性文字。
- **所有视频静音、循环、进入视口自动播放**，同一组画面之间自动保持同步（偏差 > 60ms 自动纠正，循环回到起点时也会重新对齐）。
- 页面**不放大视频**：Part 1 / Part 2 的画面一律按原始 **256×256** 显示（`.frame` 宽度 = 256 × scale，`max-width:100%` 只允许缩小）。
- 滑杆就是**一条 1.5px 的细线**（没有中间的把手），悬停/拖动时变蓝加粗；鼠标可抓的范围有 17px 宽，很好拖。
- 方法名是**横向小胶囊，压在每块画面的顶部内侧**，跟着画面宽度一起移动；画面被拖窄时自动省略号显示（鼠标悬停仍可看到全名）。某个方法缺文件时标注会变灰加删除线。
- Part 2 相邻两块画面之间最小只留 2%，所以每排的 3 根滑杆都能很灵活地来回推，方便把任意两块画面拉宽对比。
- Part 2 每排的 GT / Ours 用不同颜色标注（Ours 绿、GT 橙），一眼能分出本方法与真值。

## 4. 资源放哪里（唯一需要改的地方：`assets/js/data.js`）

### 4.1 目录与命名规则

```text
{MEDIA_ROOT}/input_videos/weather/input_{天气场景名}{EXT}  ← Part 0 的四类天气场景
{MEDIA_ROOT}/volsplat/{天气目录}/{文件名}{EXT}             ← Part 1 的基线 VolSplat
{MEDIA_ROOT}/ours/{天气目录}/{文件名}{EXT}                 ← Ours（本方法，Part 1 / Part 2 都用）
{MEDIA_ROOT}/gt/{天气目录}/{文件名}{EXT}                   ← GT（Part 2 每排最后一个）
{MEDIA_ROOT}/compare/{方法名}/{天气目录}/{文件名}{EXT}     ← Part 2 的 6 种对比方法

文件名 = {天气目录}_{场景}_{强度}_{视角}
例：demo_final/compare/AdaIR/Rain/Rain_RedHouse_heavy_view_high.mp4
```

天气目录名沿用导师给的写法：`Rain` / `Snow` / `Foggy` / `SandStorm`（页面上显示 Rain / Snow / Fog / Sandstorm，映射写在 `CATEGORIES` 的 `folder` / `label` 里）。`input_videos/intensity/` 里的 12 段视频目前没有用到，需要的话可以在 `data.js` 里加一节展示。

> **注意 Part 0 的文件名后缀用的是 `CATEGORIES` 的 `scene`，不是 `folder`。** 因为 `input_videos/weather/` 里的雾天文件叫 `input_Fog.mp4`，而同目录在别处（`ours/Foggy/`、`gt/Foggy/` 等）都叫 `Foggy`。四个值目前是 `Rain` / `Snow` / `Fog` / `SandStorm`；以后哪个输入视频再改名，改 `scene` 即可，不用动代码。

### 4.2 三种常见调整

**A. 继续用 `demo_final`**：什么都不用改。

**B. 把资源搬进项目**（例如新建 `media/` 目录）：

```js
MEDIA_ROOT: 'media',
```

**C. 换成图片**（Part 1 会自动改用 `img-comparison-slider` 图片滑杆）：

```js
EXT: '.png',            // 或 '.jpg'
NATIVE_WIDTH: 1024,     // 图片建议填真实分辨率，页面同样只缩不放
```

### 4.3 增删场景（当前 12 个：四类天气各 3 个，每类内部按 heavy → medium → light 排列）

1. 在 `CASES` 里加一行（或删一行）：

```js
{ weather: 'rain', scene: 'RedHouse', intensity: 'heavy', view: 'view_high' },
```

2. 也可以跑脚本扫目录生成这一行：

```powershell
powershell -ExecutionPolicy Bypass -File tools/scan-media.ps1
```

> 顺序就是页面顺序：**同一类天气里，`CASES` 中先写的排在左边**，所以按 heavy → medium → light 写就得到"每排从左到右 heavy / medium / light"。Part 1 的卡片标题只显示到强度（`{天气} · {场景} · {强度}`），`view` 只用于拼视频文件名。

### 4.4 Part 2 展示哪些方法、按什么顺序

```js
options: {
  part2: {
    // 6 种方法按 2 : 2 : 2 分成三排，每排一行数组
    rows: [
      ['AdaIR', 'DOD'],
      ['MoCE-IR', 'PromptIR'],
      ['ReSplat', 'WeatherRemover'],
    ],
    tail: ['Ours', 'GT'],   // 每排末尾固定跟着的两路（顺序 = 从左到右，GT 放最后）
    minGap: 2,        // 相邻两块画面之间允许的最小宽度（百分比）
    autoplay: true,
    loop: true,
  },
}
```

改 `rows` 就能调整分组、顺序与每排个数：一排里有几个 key，那一排就有几个画面（滑杆数 = 画面数 − 1）。`tail` 里的 key 会接在每一排末尾，删掉 `'GT'` 就变成"2 + Ours"。

> **关于 WeatherGS**：`demo_final/compare/` 下现在只有 6 个方法文件夹（AdaIR / DOD / MoCE-IR / PromptIR / ReSplat / WeatherRemover），所以页面就是这 6 种。以后要加方法：在 `METHODS` 里加一行，再写进 `options.part2.rows` 的某一排即可。

### 4.5 Part 1 只展示部分场景

## 5. 「256 分辨率禁止放大」是怎么落地的

| 位置                          | 做法                                                                                                                                         |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Part 0 / Part 1 / Part 2 画面 | 显示宽度 =`min(容器宽度, native-width)`（256），只允许缩小，屏幕上就是 256×256                                                            |
| Part 2 的每排画面             | 一层排一层地重叠在同一个 256×256 舞台内（7 种方法时是 7 层，现在是每排 4 层），靠`clip-path` 各显示一条竖条；舞台尺寸不变，因此也不会放大 |
| 图片（可选）                  | 页面读取图片真实分辨率作为上限（`naturalWidth`），同样只缩不放                                                                             |
| 放大查看                      | 只有**手动点击**画面才会打开灯箱（默认适应窗口，可切"原始像素"）                                                                       |

## 8. 已知限制与建议

- **视频编码**：浏览器对 H.264/MP4 支持最好；`demo_final` 里的 `.mp4` 可直接播放。若换成 HEVC 等编码可能无法播放。
- **资源自检**：控制台执行 `checkAssets()`，会检查 Part 0（4）+ Part 1（12×2）+ Part 2（12×8）= **124** 个视频路径，当前结果是全部存在（`demo_final` 里剩余未使用的视频不会出现在页面里）。
- **资源量**：Part 2 只渲染当前 Tab，切换 Tab 时才创建该类的视频；每个场景有 3 排 × 4 路 = 12 路（其中 Ours / GT 每排各重复一次，所以每类天气会复用 Ours / GT 视频）。Part 0 的 4 段视频是 30s、单个 2–7MB，其余视频都是 256×256、约 70–190KB。
- **字体/联网**：页面不请求任何 CDN，断网也能完整展示。
